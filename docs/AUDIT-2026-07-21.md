# Full-App Logic Audit - v2 (2026-07-21)

Read-only audit of `audiobook-tagger-v2` at v2.1.2 (`dd51ea4`). Six parallel review passes: test ground truth, api.js, src/lib + hooks/context, Rust backend, pages, components/modals. Every finding below was verified against the actual source by the reviewing agent (line numbers current as of this commit). No fixes applied.

**Ground truth:** JS suite 118 pass / 0 fail / 22 skipped (all skips = `useScan.test.js`, known C7c debt). Rust 7 pass / 0 fail. The suites are green because they cover almost none of the paths below.

**Status of the four open findings from the 2026-06-28 audit:**
- Audnexus/OpenLibrary bypass `proxyFetch` - STILL PRESENT (`api.js:524,565`), and those fetches also have no timeout.
- `parseAIJson` throws on prose-wrapped JSON - STILL PRESENT (`proxy.js:351-363`). Live failure path for Anthropic models (no JSON mode).
- `validateYear` pre-1900 rejection - FIXED on the live path (`fix_years_batch` uses its own `isValidYear`); the old helper remains as a dead-code trap in `normalize.js:395`.
- `import_from_abs` pagination spin - STILL PRESENT (`api.js:355-361`), duplicated in `abs-client.js:48-55`. Also exits early importing only page 1 if the server omits `total`.

Also verified fixed: narrators `"[object Object]"` (`abs-client.js:135`), the "Unknown Series" remap (gone from v2 scanner.rs), stripEmbeddedSequence on both ABS write branches.

## CRITICAL - crashes, data loss, or features that cannot work

**CR-1. Failed rescan silently deletes the selected books from the session.** `src/hooks/useScan.js:312-347`. The inner catch swallows the scan error, then the group-replacement `setGroups` runs anyway: every group containing a selected file is filtered out and nothing is appended. Returns `{success: true, count: 0}`. Select 200 books, Clean Scan, backend errors -> all 200 books and every staged edit vanish.

**CR-2. One failed per-book lookup crashes the whole app.** `src/pages/ScannerPage.jsx:756-768` (Fix Titles) and `1315-1328` (Fix Series). The per-book catch resolves `{groupId, error}` with no `result` key, but the setGroups updater dereferences `result.success` unconditionally. The TypeError thrown inside the updater propagates to the top-level ErrorBoundary, unmounting AppProvider: all groups and unsaved edits lost. One network blip in a 50-book Fix Titles run = white screen.

**CR-3. ABS-imported files have no `id`; selection Set membership of `undefined` wildcards write/rename to the whole library.** `src/lib/abs-client.js:168-174` builds files without `id`. Selecting any ABS group adds `undefined` to `selectedFiles`; `useTagOperations.js:62` `selectedFiles.has(file.id)` is then true for every ABS file in every group. Confirming a rename for one ABS book sends file pairs for the entire library; write's filesMap collapses all ABS entries onto the key `undefined`.

**CR-4. Partial metadata pushes wipe curated series in ABS.** `src/api.js:308-310`: `buildAbsPayload` always includes `series`, defaulting to `[]`, while every other absent field is omitted from the PATCH. Any push whose input lacks series info (e.g. `push_abs_imports` with sparse metadata, genre/tag-only updates) sends `series: []` and destroys the curated series server-side. Compounded by `api.js:685-686`: `resolve_metadata_batch` turns "AI omitted the series key" into `series: null` + `changed: true` (title/author fall back to current values; series does not), which flows through ScannerPage into `series: []` on push. Indistinguishable from a legitimate standalone answer.

**CR-5. Validation review for a selection can never show anything.** `src/components/ValidationIssueModal.jsx:57-59` filters `groups` by `selectedBooks.has(g.id)`, but `selectedBooks` is ScannerPage's `selectedFiles` (file ids, different UUIDs). With any selection active the modal always reports "No validation issues found!" and offers zero fixes.

**CR-6. Rename preview lies twice.** (a) The template the user picks is only used for the preview; `onConfirm` calls `renameFiles(...)` -> `rename_files` with no template, so files are renamed with the backend default (`RenamePreviewModal.jsx:53-59` vs `ScannerPage.jsx:3234-3237`). (b) The preview passes the focused group's metadata for files spanning all selected groups (`ScannerPage.jsx:3233`), while the real rename correctly uses per-group metadata: the names shown are wrong for every non-focused book.

**CR-7. Saving an edited author description throws ReferenceError.** `src/pages/AuthorsPage.jsx:468-471` calls `setDetail`, which `useAuthors()` never exports. The path can never have worked; the change is staged but the handler crashes.

**CR-8. Embedded series tags are never read from m4b files.** `src-tauri/src/scanner.rs:111-132`: `lookup_txxx` compares against `ItemKey::Unknown("SERIES")`, but lofty keys MP4 freeform atoms as the full `"----:com.apple.iTunes:SERIES"` string (verified in lofty 0.19.2 source), and maps `MVNM`/`MVIN` to known keys for mp3. So series/series_number embedded tags are invisible for the app's primary format, and the buggy folder heuristics below always take over.

## HIGH

### Batch AI handlers (api.js, prompts.js)
- **Positional matching contaminates books.** `api.js:916-918` (classify): results matched to books purely by array index, and the output schema requests no id (prompts.js:302-309). A model that skips/merges one book shifts every subsequent book's genres/tags/age rating onto the wrong book, written as `success: true`. `api.js:731` (resolve) has an id fallback but checks position first, so a shifted array still mis-assigns.
- **Classify replaces the tags array unguarded.** `ScannerPage.jsx:2280-2285`: genres/themes/tropes only apply when non-empty, but `tags` is always replaced. A book with 15 curated tags that merely lacks a `dna:` tag gets swept into classification and its tags replaced by whatever small set the AI returns.
- **fix_authors AI format feeds a corrupting normalizer.** `normalize.js:314-322` treats any 2-part comma string as "Last, First": `"Stephen King, Peter Straub"` -> `"Peter Straub Stephen King"`. The Fix Authors prompt (`api.js:1294`) explicitly requests comma-separated co-authors and pipes the response through `cleanAuthorName` (`api.js:1299`), so every co-authored book fixed by AI is garbled. Related: `buildAbsPayload` (`api.js:265`) splits authors on bare comma, so `"Martin Luther King, Jr."` becomes two ABS authors on every push.
- **Tag mapping reverse containment.** `genres.js:459-464`: `mapTag("fantasy")` -> `"fantasy-romance"` (first compound tag in list order containing the token); same for romance -> contemporary-romance, thriller -> legal-thriller, mystery -> cozy-mystery. Same bidirectional logic in `mapGenre` (429-433).
- **fix_authors counts "AI confirmed existing author" as failure.** `api.js:1302-1322`: with `force: true` over a correct library, every book reports `success: false` / "AI could not identify an author".
- **Narrator-only resolutions are discarded.** `api.js:692-695`: `changed` excludes narrator, and ScannerPage skips the merge when `!r.changed`. Also type-sensitive (numeric vs string sequence -> spurious changed).

### Write/rename/push pipeline (the "results never reach disk" cluster)
- **Enrichment and inline edits never enter `file.changes`, so Write Tags ignores them.** `useTagOperations.js:16-31` writes only `file.changes`; Fix Authors/Titles/Years/Classify/Resolve and MetadataPanel inline edits update only `group.metadata`. Users see corrected data in the UI, hit Write, and the files keep the old tags. MetadataPanel's "Save Local" (`MetadataPanel.jsx:293-298`) just clears the dirty flag and shows "Saved!" - a placebo.
- **WritePreviewModal (review/exclude/backup UI) is dead code**; the real write is `writeSelectedTags(files, false)` - immediate, no preview, backups hardcoded off (`ScannerPage.jsx:519`).
- **"Select all filtered" breaks all file-based ops.** `ScannerPage.jsx:237-249` sets only group ids and clears `selectedFiles`; Write/Rename/Rescan then operate on an empty set ("No Changes" toast despite visible pending changes).
- **Run All feeds every step stale inputs.** `ScannerPage.jsx:1889-1895`: each step handler closes over the pre-Run-All `groups`, so step 5 classifies with the garbage title step 2 just fixed.
- **Author push clears staged renames/merges even on partial failure** (`useAuthors.js:362-389`), and AuthorsPage ignores the returned failure summary: failed edits unrecoverable, user not told.
- **Settings shows "Saved!" when the save failed.** `SettingsPage.jsx:390-397`: `saveConfig` returns `{success:false}` instead of throwing, so the catch is dead. Same false-confirmation on Clear All Keys (`SettingsPage.jsx:1285-1292`) - security-relevant.
- **BulkEditModal series checkbox nulls what you leave blank.** `BulkEditModal.jsx:62-65`: check Series, type the name, leave "Book #" blank (each book has its own) -> every selected book's sequence set to null.
- **JSON import silently discards data.** `ExportImportModal.jsx:80-89` reports "Loaded N books"; the ScannerPage handler for full imports is a stubbed `return` (`ScannerPage.jsx:432-437`). The advertised backup round-trip is one-way.
- **Bulk cover auto-match is greedy with a 0.9 substring rule.** `BulkCoverAssignment.jsx:13-15, 78-99`: "Harry Potter" claims `harry_potter_2.jpg` as an "Excellent match"; dropping one more image re-runs auto-match and wipes manual corrections (128-133).

### Rust backend
- **Standard "NN - Title" book folders are classified as chapter folders** (`scanner.rs:199, 542-568`) - the app's own test fixture uses this naming. Group name climbs to the parent, so title becomes the series folder name. Multi-disc books (`Disc 1/`, `Disc 2/`) produce duplicate BookGroups (renamed but never merged) and the book title gets written as the series (`scanner.rs:296-314`).
- **Deep paths without a root marker misattribute mounts as authors** (`scanner.rs:296-309`): `/Volumes/USB/Stephen King/The Talisman/x.m4b` -> author "USB", series "Stephen King". Root-marker match uses `ends_with`, so publisher folder "Graphic Audio" becomes the library root (`scanner.rs:269`).
- **"Catch 22" still invents a series** (`scanner.rs:440-454`): any standalone title ending in 1-2 digits ("Mila 18") -> series "Catch"/"Mila". Still present from the June audit.
- **UTF-8 panic on Whisper output.** `whisper.rs:627` slices `&transcript[..800]` by bytes; a multi-byte char at the boundary panics the async command mid-batch. Routine for non-English or curly-quote transcripts.
- **macOS no-Homebrew whisper install installs a non-executable and reports success.** `whisper_local.rs:290-299, 450-479`: downloads an xcframework (headers/dylibs, no CLI), copies the first `whisper*` file as the binary, chmods it, passes the corruption guard, reports installed=true; every transcription then fails. Worse, `Command::new("brew")` fails under the Finder-launched GUI PATH (`whisper_local.rs:280`), so even Homebrew users are routed into this path. Linux users get told to install Homebrew (`whisper_local.rs:224, 301`; the intended fallback error at 301 is unreachable dead code - confirmed by cargo warning).
- **ollama.rs omits `/opt/homebrew/bin`** (`ollama.rs:82`) while `find_ffmpeg_binary` includes it: Homebrew Ollama on Apple Silicon (the primary dev platform) is reported "not installed". And **on every window close the app runs `pkill -f "ollama serve"`** (`ollama.rs:241-243`, `lib.rs:32-37`), killing any Ollama on the machine including ones the app didn't start.

## MEDIUM (selected; full agent detail below the fold)

- Undo restores files on disk but the UI keeps post-write state with green checkmarks; user can re-write the bad data (`ScannerPage.jsx:71-78`).
- Transient whisper/extraction failures (missing API key, ffmpeg error) are cached permanently as empty transcripts; the single-item command has no force bypass (`whisper.rs:202-211, 76`).
- `cleanup_temp_files` deletes `.tmp*` audio in the shared system temp dir, including a concurrently running batch's files, whose resulting empty output then gets cached (`whisper.rs:575-589`).
- Whisper model downloads write directly to the final path; a failed download leaves a truncated model that the exists-check treats as complete (`whisper_local.rs:512-543`).

- Edit-modal save fabricates diffs (`old: ''`), drops cleared fields (clearing narrator produces no write change), and never maps subtitle/isbn/asin/language into `file.changes` (`ScannerPage.jsx:260-334`).
- EditMetadataModal genres input eats commas on every keystroke; genres can only be added by pasting. Crashes if `genres` is missing (`EditMetadataModal.jsx:24-27, 324`).

- Custom system prompt honored by about half the AI handlers (classify/description/authors) and silently ignored by the rest (resolve/titles/series/genres/subtitles/years/age) (`api.js` multiple).

- push handlers invert id preference (`abs_id || id` vs `id || abs_id`) -> 404s for matched local scans (`api.js:378` vs `405`).
- Auto-detect re-enables Local AI the user explicitly turned off (`AppContext.jsx:43-62`); SettingsPage 5s Ollama poll resets the model dropdown and persists stale config (`SettingsPage.jsx:199-232`); whisper install/uninstall mutate config without persisting (`SettingsPage.jsx:308, 333`).
- Success/failed counters mutated inside setGroups updaters (double-count under StrictMode); Fix Titles/Series never count rejections as failures (`ScannerPage.jsx:771+`).
- SeriesIssueModal fix map keyed `bookId-field` collides; unchecking one fix can toggle another while the first still applies (`SeriesIssueModal.jsx:120-123`). Three review modals use `useState` as if it were `useEffect` (`SeriesIssueModal.jsx:31`, `ValidationIssueModal.jsx:130`, `AuthorAnalysisModal.jsx:89`).
- performLookup stamps the first Open Library hit's first ISBN with no title/author verification (`performLookup.js:48-59`).
- Bulk cover apply closes and reports success on partial failure (`BulkCoverAssignment.jsx:240-263`); cover caches never invalidate, so new covers don't appear until restart (`BookList.jsx:568`, `MetadataPanel.jsx:166`).
- Shift-click range mixes filtered/unfiltered indices (`ScannerPage.jsx:166-180`); push modal previews a snapshot but pushes the live selection (`ScannerPage.jsx:2891-2920`); tab switch unmounts ScannerPage mid-operation, allowing duplicate concurrent batches (`App.jsx:66-81`).
- `scan_library` and ffmpeg/whisper child processes run blocking inside async commands; cancel only takes effect between items (`scanner.rs:607`, `whisper.rs:297+`).
- `ollama_start` with a remote base_url spawns a local ollama pinned to localhost but health-polls the remote, then reports failure while leaving the orphan running (`ollama.rs:188-221`).

## Suggested fix order

1. **Data-loss / crash cluster (small diffs, huge payoff):** CR-1 (guard rescan failure), CR-2 (guard `result` in updaters), CR-4 (omit `series` from payload when input has none; treat missing AI series key like missing title), CR-3 (give ABS files real ids at import), CR-7 (export or drop `setDetail`).
2. **Trust cluster:** CR-5 (filter by group ids), CR-6 (pass template through or preview per-group), false "Saved!"/false import-success/partial-failure-clears (H items), undo UI refresh.
3. **Write-path cluster (design decision needed):** either enrichment results populate `file.changes`, or Write derives changes from `group.metadata` vs on-disk tags. This is the biggest logic gap in the product: AI fixes currently never reach local files.
4. **Batch integrity:** echo ids in classify output schema and match by id everywhere; guard tags like genres.
5. **Rust scanner:** fix lofty key lookup (CR-8), chapter-folder misclassification, root-marker `ends_with`, Catch-22 pattern.
6. **Environment/lifecycle:** GUI PATH for brew/ollama, remove xcframework install path, scope the Ollama kill to the PID the app spawned, UTF-8-safe truncation.
