# Full-App Audit - v2.2.3 (2026-11-12)

Read-only audit of `audiobook-tagger-v2` at v2.2.3 (`ad87f38`). Five parallel review passes: Rust write/scan/session backend, Rust whisper/Ollama installers + CI, `api.js` + `src/lib`, ScannerPage + hooks + context, and settings/modals/onboarding. No fixes applied, nothing committed.

**Ground truth:** vitest 623 pass / 22 skipped (the known `useScan.test.js` debt), cargo 95 pass / 0 warnings, `npm audit --omit=dev` 0 vulnerabilities. `cargo audit` is not installed and was not run. The suites are green because they cover the lib functions, not the wiring between them.

**Verification labels used below**
- **Confirmed** - the lead re-checked it against the source or re-ran it after the reviewer reported it.
- **Reproduced** - the reviewer ran the real code (throwaway script or fixture files in `/tmp`); the lead did not re-run it.
- **Traced** - read-only trace by the reviewer; not run.
- **Unverified** - plausible, but a link in the chain was not checked. Stated per item.

Nothing here was tested in a built app, and nothing was run on Windows or Linux.

---

## The headline: half the app has no buttons

`src/components/scanner/ActionBar.jsx` receives `onScan`, `onRescan`, `onPipelineRescan`, `onWrite`, `onRename`, `onBulkEdit`, `onBulkCover`, `onOpenRescanModal`, `onScanErrors`, `onAuthorMatch`, `onSeriesAnalysis` and `onBatchFix` (lines 40-50, 71-73, 103) and renders a control for none of them. `BookList.jsx` does not use `onScan`, `onImport`, `onExport` or `onCleanupAllGenres`. `git log -S onScan` shows only the April scaffold commit, so these were never wired in v2. **Confirmed** (grep count of 1 per prop in ActionBar, 0 in BookList).

What a user can actually do: Import from ABS, the Enrich menu, Push, DNA, Force, Select All / Clear, and inline edits in the metadata panel.

What cannot be reached: local folder scan, Write Tags, Rename, Undo, Rescan, Bulk Edit, Bulk Cover, export/import, validation, author and series analysis, batch fix, the edit modal, and the Authors page (`App.jsx:13` mounts only `scanner` and `settings`). The Rust commands behind scan/write/rename/undo are registered and tested (`src-tauri/src/lib.rs:13-19`).

Consequences:
- **GitHub issue #62 is correct.** There is no way to scan a local folder or write tags to files, under any setting. The empty state (`BookList.jsx:623-677`) offers only ABS. The README (line 24) advertises "Local folder scanning ... without needing an ABS server".
- Onboarding can be skipped without ABS (`OnboardingWizard.jsx:63-71, 412-427`), but every step is ABS or cloud-key specific and nothing says skipping is allowed.
- The July audit's writer work (W-series below) protects a feature nobody can open. Those bugs become live the moment the buttons are added, so they are listed as "fix before wiring".
- Wiring alone is not enough: `get_scan_progress` and `cancel_scan` are JS stubs (`api.js:1843-1844`), `handleImport` calls a command that does not exist (`import_folders`), and pushing a folder-scanned book fails with "Missing item ID" (`useTagOperations.js:141-149` vs `api.js:349-350`).

## CRITICAL - reachable today, destroys curated ABS data on Push

**C-1. Force + Classify with an empty AI answer wipes genres and tags.** `ScannerPage.jsx:2676-2683`, `api.js:879-887`, `absPayload.js:146,163`. Force blanks `genres`/`tags` before the merge; an empty or unusable AI answer still counts as success; Push then sends the empty arrays as a deliberate clear. **Confirmed**: `buildAbsPayload` returns `{"metadata":{"genres":[]},"tags":[]}` for that state. **Unverified**: how often a model returns an empty answer (M-1 below is one way).
Even with a good answer, Force drops every curated tag the AI did not return.
Fix: fail the result when genres and tags are both empty; only send `[]` when a user edit flagged the clear.

**C-2. "AI Tags" and "Generate DNA" replace the tag list instead of merging.** `ScannerPage.jsx:2375-2384` sets `metadata.tags = suggested_tags`; `api.js:1239-1259` swallows a failed DNA call and still reports success. **Confirmed**: a book with `['favorite','dna:pacing:fast']` pushes `tags:["fast-paced","found-family"]`. Generate DNA strips all existing `dna:` tags even when the AI returns `{}` (`api.js:1515-1523`, `ScannerPage.jsx:2541-2553`) - **reproduced** by the reviewer.
This contradicts the v2.2.3 guarantee that AI tags merge. Only Classify goes through `mergeClassifyTags`.
Fix: route both through `mergeClassifyTags` with `abs_original.tags`; never strip `dna:` tags when zero new ones came back.

**C-3. Multi-series books get a junk series on any series write.** `api.js:1917-1921, 1947`, `absPayload.js:59-74, 98-120`. The import assumes ABS returns a `metadata.series` array. It does not: **confirmed against the live server**, `/api/libraries/:id/items?expanded=1` returns only `seriesName` (for example `"The Plantagenet and Tudor #6, Tudor Court #1"`), so `all_series` is always empty and the whole string becomes one series name. Editing the sequence, an AI series resolve, or a push with no snapshot then sends a mangled or single series (payloads **reproduced** by the reviewer). Single-series strings like `"Rivers of London #9"` round-trip correctly.
Exposure in the Secret Library: 4 of 2,742 books today.
Fix: fetch the real series array (`/api/items/:id?expanded=1`) before any series write, or refuse to send series when the name contains more than one `#`.

**C-4. Fix Authors rewrites correct names, with no AI involved.** `normalize.js:347` (`cleanAuthorName`), `api.js:1335-1341, 1372`. **Confirmed** by running the function:

| Input | Output |
|---|---|
| Don DeLillo | Don Delillo |
| Tim O'Brien | Tim O'brien |
| Mary McCarthy | Mary Mccarthy |
| Ta-Nehisi Coates | Ta-nehisi Coates |
| CS Lewis | Cs Lewis |
| Homer, Emily Wilson | Emily Wilson Homer |

Each difference is returned as `fixed: true`, staged, and pushed; ABS then creates a new author and unlinks the book from the curated one.
Fix: never change the casing of a name that already has mixed case; require two or more words on both sides of a comma before treating it as "Last, First".

## HIGH

### Push and AI layer

**H-1. Default Classify replaces curated genres.** `mergeGenres.js:33-38`, `ScannerPage.jsx:2692-2697`. With `preserve_existing_genres` off (the default) the AI list replaces the book's. **Confirmed**: `['Cozy Witchy','Biography, Memoir','Fantasy']` + AI `['Fantasy','Adventure']` gives `['Fantasy','Adventure']`. This is the documented #54 default, but books are sent to Classify merely for lacking DNA or age tags, and it is the same shape as the February genre corruption. Decision needed: flip the default to supplement.

**H-2. Year edits are never pushed when the book already has a year.** `absPayload.js:31` reads `published_year`; Fix Years (`ScannerPage.jsx:1384`) writes only `metadata.year`. **Confirmed**: 1999 changed to 2005 yields `{"metadata":{}}`, and the push counts it as updated. The inline Year edit has the mirror bug: it writes `published_year` only, so the header and Year sort stay stale (`MetadataPanel.jsx:863`).

**H-3. Five AI actions never apply a result.** The handler returns a different shape from what the caller checks, so the AI call is paid for and nothing changes. **Traced**; the Fix Titles mismatch is **confirmed** (`api.js:808-824` returns flat fields, `ScannerPage.jsx:1010, 1028` requires `result.success && result.result`).

| Action | Handler (`api.js`) | Caller expects (`ScannerPage.jsx`) |
|---|---|---|
| Fix Titles | 808-824, flat fields | `result.success && result.result` (1010, 1028) |
| Fix Series | 827-844, parsed object | same (1626, 1645) |
| Fix Subtitles | 1293, no `fixed` | `subResult.fixed` (1125) |
| Clean Genres (AI) | 1195, `genres` | `changed`, `cleaned_genres` (886) |
| Lookup Age | 1546, `age_rating` | `age_category` / `age_tags` (1724, 2450) |

**H-4. Books without an import snapshot push every field.** `absPayload.js:187, 219-223`, `session.js:17, 114-132`. `SESSION_VERSION` is written and never checked, so a session saved before v2.2.3 restores groups with no `abs_original`, and the fallback sends title, authors, narrators, series, all genres and all tags. **Reproduced** (payload); restore path traced.

**H-5. A stale snapshot overwrites newer server-side tags and genres.** `api.js:262-270`, `useScan.js:41-77`. Tags and genres go out as whole arrays built from the import-time list, and Push never re-reads ABS. Re-import does not refresh a book that was ever edited, because nothing clears `total_changes` after a successful push (`absPush.js:203-210`). Add a tag in the ABS UI, then push any tag change from the app: the ABS-side tag is deleted. **Traced.**

**H-6. Browser build only: the proxy fallback sends the ABS token to a third-party host.** `proxy.js:7, 52-66`. **Confirmed**: any failed direct fetch, not only a CORS failure, is re-sent to the default `https://audiobook-tagger-proxy.workers.dev/proxy` with the `Authorization` header in the body. The desktop app goes direct and is unaffected. The web repo fixed this on 2026-10-28; this copy was not updated. **Unverified**: who controls that workers.dev host.

### Scanner page

**H-7. Cancel does not cancel an import or a push.** `useScan.js:891-917`, `api.js:1844` (`cancel_scan: () => {}`). **Confirmed.** The bar disappears and the work continues. `ABSPushModal` never sees a busy state for the ABS path, so a second Confirm click under 100 books starts a second concurrent push (traced).

**H-8. "Select All" ignores the active search filter.** `ActionBar.jsx:485-491` calls `selectAll(groups)` (`ScannerPage.jsx:403-406`). **Confirmed.** `handleSelectFiltered` exists and is never called. Search "Sanderson", Select All, Run All: the whole library is processed.

**H-9. A failed ABS import shows nothing.** `useScan.js:531-536` rethrows; the caller is bound straight to `onClick` with no catch. **Confirmed.** `hasAbsConnection` checks URL and token but not the library id, so the button is offered in exactly the state that throws.

**H-10. The onboarding "Import Library" step discards the import.** `OnboardingWizard.jsx:183` dispatches `wizard-import-complete`; nothing listens. **Confirmed** (one occurrence in `src`). The user sees "Imported N books", then an empty library.

### Settings

**H-11. Three settings are saved and never read.** **Confirmed** by grep: `concurrency_abs_push` ("ABS Push Workers"), `local_concurrency` ("Local AI Workers") and `custom_approved_genres` ("Approved Genres") have no reader outside `SettingsPage.jsx`. Pushes are sequential. README lines 26 and 51-53 tell NAS users to lower the push workers.

**H-12. Local AI cannot be enabled when Ollama already runs outside the app.** `SettingsPage.jsx:577-595, 1059-1069`. The only toggle is labelled by whether Ollama is running, so it always reads "Stop Local AI"; clicking it sets `use_local_ai: false` and nothing sets it back. A user with an OpenAI key and a system Ollama keeps being billed. **Traced.**

### Installers (whisper / Ollama)

**H-13. macOS FFmpeg auto-install is dead.** `whisper_local.rs:481`. **Confirmed**: `https://evermeet.cx/ffmpeg/getrelease/zip` returns HTTP 410 "API endpoint removed due to exorbitant abuse". Install Local Whisper fails on any Mac without a system ffmpeg.

**H-14. Windows whisper install copies the wrong executable.** `whisper_local.rs:606-642`. The reviewer listed the pinned v1.8.4 archive: everything is under `Release/`, the fallback walk accepts `main.exe` (a deprecation stub), and the DLLs `whisper-cli.exe` needs are not copied. The code matches (**confirmed**); behaviour on Windows is **unverified** - not run.

**H-15. Executables are downloaded and run with no integrity check.** `ollama.rs:340-356`, `whisper_local.rs:485, 498-500`. Ollama (macOS/Linux) comes from a floating "latest" URL with no hash; Linux FFmpeg likewise; the Windows FFmpeg hash is fetched from the same host as the zip; whisper models are unpinned. Only whisper.cpp is pinned and hashed. **Traced** plus header requests.

**H-16. Only the `ollama` binary is copied out of the archive.** `ollama.rs:388-390, 415-417`. The current release ships `llama-server` and several libraries beside it. **Unverified** whether inference works without them.

## MEDIUM

**M-1. A truncated AI response is salvaged as a fragment and treated as complete.** `proxy.js:421-436`; no check of OpenAI `status: incomplete` or Anthropic `stop_reason: max_tokens`. A DNA answer cut mid-array becomes `["dna:length:2"]` and replaces the real DNA tags. Feeds C-1. Reproduced.

**M-2. No HTTP timeouts in the desktop app except for Ollama.** `proxy.js:34-41, 143-151, 192-215`: the Tauri fetch ignores `timeoutMs`. A stalled ABS or provider hangs a push or batch indefinitely. No retry on 429 either. Traced.

**M-3. AI and lookup results applied with no confidence or placeholder check.** `api.js:694, 708, 589-601, 1809`. `"series": "N/A"` replaces a curated primary series (reproduced); `confidence` gates nothing; the first OpenLibrary hit is labelled "Audible" in the prompt (traced).

**M-4. Description Processing stages garbage narrators.** `ScannerPage.jsx:2167`. **Confirmed**: the regex carries `/i`, so `[A-Z]` matches lowercase. "Read by the author with a full cast" stages narrator "the author with", which goes out on Push.

**M-5. Fix Series keeps the old series as a second series.** `ScannerPage.jsx:1645-1647`. **Confirmed**: the new name is prepended and the old entry kept. Currently masked by H-3 (Fix Series never applies); it goes live when H-3 is fixed.

**M-6. Enrich cannot be cancelled and stages nothing until the whole selection finishes.** `ScannerPage.jsx:2014, 2159, 2653`. A crash or quit mid-run loses the step. Traced.

**M-7. Operations look the same on total failure and on success.** Fix Titles/Series/Age end with no toast; Subtitles/Descriptions/Tags/Genres log to console only; audio check shows a green "Updated 0 of N". Traced.

**M-8. Genre cleanup silently downgrades for Anthropic and Ollama users.** `ScannerPage.jsx:835-844` gates on `openai_api_key`; the static path gives no feedback and its results are dropped by the next Import. Traced.

**M-9. Push results cannot be tied to books, and no-ops count as updates.** `api.js:389-392, 264`. Errors carry no id or title. Reproduced.

**M-10. The push modal still describes the old overwrite behaviour.** `ABSPushModal.jsx:101, 170`. **Confirmed**: "will be replaced with what you see in the tagger". The diff-only wording was fixed in the web repo only. The breakdown also counts per file, not per book.

**M-11. Settings edge cases.** Auto-saving controls persist every other unsaved edit and skip URL validation (`SettingsPage.jsx:915-918`); "Start Local AI" with no models selects `gemma4` and reports success (`:586`); an Anthropic-only user finishes the wizard with an OpenAI model selected (`OnboardingWizard.jsx:194, 320`). Traced.

**M-12. Installer and process issues.** Total-request timeouts too short for the payload (a 9.6 GB model pull has 20 minutes, `ollama.rs:458`); a failed model pull reports success because the `error` field is never read (`ollama.rs:483-509`, **confirmed**); ffmpeg/whisper children have no timeout and ignore Cancel (`whisper.rs:476-516`); the ABS token is passed on ffmpeg's command line (`whisper.rs:459`); console windows flash on Windows (`whisper.rs:528`). Traced.

**M-13. Release pipeline.** `.github/workflows/build.yml`: a manual run on `main` would create a release and tag named `main`; `contents: write` is granted to every job while two third-party actions are on mutable refs; artifacts are ad-hoc signed, not notarized, with no checksums. Traced.

## Fix before wiring Write / Rename / Scan (unreachable today)

**W-1. The scanner merges different books that share a folder.** `scanner.rs:723-735, 757-766, 781-785`. `1984.m4b` + `Animal Farm.m4b` become one book "1984"; so do MP3s with a title and no album. A write then stamps one book's metadata on the other and rename calls them Part 01 / Part 02, with no undo. Reproduced.

**W-2. Editing a multi-file book's title overwrites every track title.** `writer.rs:112-115`. Album is never written, so a rescan shows the old title. Traced.

**W-3. MP3s with a lyrics (USLT) frame can never be written.** `writer.rs:413-429`. Fail-safe. Reproduced.

**W-4. Per-track m4a/m4b books split into one book per file.** `scanner.rs:759-762, 821-829`. Reproduced.

**W-5. A crash mid-write leaves a temp copy the next scan treats as part of the book.** `writer.rs:312`, `scanner.rs:185-189`. Reproduced. `write_tags` is also a synchronous command, so a large batch would freeze the window (traced).

**W-6. The undo journal is rewritten non-atomically.** `writer.rs:562-573`. `session.rs` already has the right pattern. Traced.

**W-7. Smaller write bugs.** Decimal series numbers on MP3 are written but not read back; filenames over about 210 characters cannot be tagged; braces in metadata corrupt the rename result; writing a year to m4b keeps the old month and day. All reproduced.

**W-8. Handler defects.** `handleScan` replaces the workspace without confirmation; several unwired handlers `setGroups` from a stale closure across an await; `handleBulkSave` dereferences `file.changes.author` unguarded; many enrich handlers never stamp `file.changes`, so a wired Write Tags would skip their results (`ScannerPage.jsx:3113-3267, 512-544`). Traced.

## Checked and found sound

- Push: genre/tag diffs are order- and case-insensitive; scalars, authors and narrators are never sent empty; placeholder "Unknown" values are never pushed; the snapshot advances only for books that succeeded; a retry is idempotent; no auto-push anywhere.
- Batch results are matched by group id through functional updaters, with the selection snapshotted at start.
- Import pagination handles a missing `total` and a full last page.
- Secrets: the session file holds only groups; logs carry counts and error text; key inputs are masked. No `dangerouslySetInnerHTML` anywhere; CSP is `script-src 'self'`.
- Session: atomic snapshot, 100 MB cap, corrupt snapshots never overwritten without an explicit discard.
- Writer: the original file is untouched on every induced failure; existing rename targets are refused; metadata cannot escape the book folder; tags outside the edited set survive a write on MP3, FLAC, Opus and MP4.
- Installers: whisper.cpp is version-pinned and hashed; zip-slip guard; arguments passed as argv with no shell; an Ollama the user already runs is detected and never killed.
- Large libraries: the book list is windowed and filters are memoised.
